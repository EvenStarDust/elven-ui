# 0005. A one-glyph font for password masks

- Status: Accepted
- Date: 2026-10-06

## Context

Password fields hide what is typed behind dots, and the dots are the one
part of a themed `Input` that still looks like the browser's. No CSS
property changes the mask character. `-webkit-text-security` only offers
a few plain shapes and isn't supported everywhere. Drawing our own marks
over a transparent field breaks the caret, selection, IME input and
pasting.

The browsers do draw the mask character in the field's own font: U+2022
in Chrome and Safari, U+25CF in Firefox.

## Decision

- The library ships one font, "Elven Mask". It has a single glyph, the
  Evenstar of the icon set, mapped to U+2022 and U+25CF. Its
  `unicode-range` covers only those two characters, so no other text ever
  uses it.
- The font is generated by `scripts/build-mask-font.mjs`, plain Node with
  no dependencies, which writes it into `src/tokens/mask-font.css` as a
  ~1 KB TrueType data URI. The glyph's geometry lives in the script, not
  in a binary file kept by hand.
- Password fields use `--elven-font-password` (the mask font, then the
  body font) and the AA-safe gold, `--elven-color-ornament-text`. Setting
  the token to `var(--elven-font-body)` brings back the browser's dots.

## Consequences

- The field behaves like any password field: caret, selection, pasting,
  autofill and screen readers are unchanged, because the value and the
  masking are still the browser's.
- It is an exception to "the library loads no fonts". It is small,
  inline (no extra request) and can be turned off with a token.
- `styles.css` grows by about 1 KB.
- To change the star, edit the script and run it again; never edit the
  generated CSS.
- A browser that masks with a character other than those two shows its
  own dots, in gold.
